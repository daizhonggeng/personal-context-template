# 隐私与发布

[返回首页](../README.md)

公开模板和个人实例应分别维护。模板只包含空白结构、通用规则及明确标注的虚构示例；填写后的实例保存真实个人资料，默认保持私有。

## 创建私有实例

使用 GitHub 模板功能创建新的私有仓库，或将模板下载到自己的受控存储。不要在公开 Fork 中填写隐私，也不要先公开提交真实资料再修改可见性。

在首次填写前确认仓库可见性、协作者、应用授权、自动化任务及备份位置。私有仓库限制访问，但不等于端到端加密，也不能控制资料被接入后的处理方式。Git 远程服务、本地设备、备份和 AI 服务需要分别管理权限。

## 内容分级

| 内容 | 建议处理 |
| --- | --- |
| 通用结构、空白模板、虚构示例 | 可以进入公开模板 |
| 个人背景、偏好、目标及普通领域记录 | 私有实例，按需提供给 AI |
| 健康、财务、家庭、法律等敏感资料 | 按必要性单独授权，可使用独立受控存储；AI 只读必要片段 |
| 密码、API Key、私钥、恢复码、完整敏感号码 | 不进入本库，使用专用凭据管理工具 |
| 第三方资料 | 只保存获授权且完成目的所需的最少信息 |

资料头部使用 `敏感级别` 和 `AI读取` 标注范围。`AI读取` 默认“需确认”，高敏资料默认“禁止”。这些标记需要应用配合执行；不能只依赖一行 Markdown 来隔离敏感内容。

账号或证件目录只保存必要索引，例如用途、办理事项或受控保管位置，不保存完整秘密。索引本身也可能暴露身份、关系或资产信息，同样需要保护。

## 向 AI 或索引服务提供资料

每次接入都应明确来源、文件范围、用途、可执行操作和撤销方式。不要把“能访问本地目录”视为“允许扫描所有文件”，也不要把“允许检索”视为“允许自动写入或训练”。

不自动导入邮件、聊天、网盘或其他来源。个人主动撰写的日记可以作为私有记录，但不能因此把会话原文、聊天转录或工具日志批量归档。

核对应用的数据存放位置、保留期限、外部模型调用和删除机制。嵌入向量、摘要、缓存、访问日志及备份也可能包含或关联个人信息；删除原文件后，还需按使用过的服务处理这些副本。

## 备份与删除

私有实例仍需独立备份，备份应控制访问，并根据内容敏感程度加密。定期验证能恢复，恢复凭据与备份本体分开保管。

Git 会保留历史。删除当前文件不能清除早期提交、克隆、索引或备份。若秘密意外提交，先撤销或轮换相关凭据，再处理历史及副本；仅删除一行不能解决泄露。

资料不再需要时，检查本地、远程、共享副本、检索索引、模型服务缓存和备份的保留安排。移入 `99-归档` 仍是保留，不是删除。

## 对外发布前

只从通用模板贡献改进，逐项查看待提交内容和完整 Git 历史。检查文字、文件名、链接、图片、附件与元数据，不要夹带真实姓名、邮箱、地址、设备标识、私人域名、内部服务信息或可识别的组合信息。

公开 Issue、Pull Request、自动化输出及截图也属于发布。需要举例时重新撰写明确标注的虚构示例，不从私有实例复制后简单打码。
